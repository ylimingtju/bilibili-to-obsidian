# 更新投资核心文件

两份核心文件分别回答“这类决策怎么想”和“相关证据在哪里”。用户发起更新时才整理材料。

## 找到知识库和待处理材料

按用户指定的库、环境变量 `BILIBILI_OBSIDIAN_VAULT`、当前目录逐级向上的顺序定位。前两种方式若指定了错误目录，请用户修正。库应含 `AGENTS.md`、`方法论/学习目标.md` 和 `raw/B站/`。首次建库可用项目 README 所示的空库模板。先读根目录协作规则和最新学习目标，按库规确定可写范围。

以下命令中的 `<脚本>` 是本技能自带的 `scripts/progress.py` 的路径，`<知识库>` 是已确认的库根。Windows 可将 `python3` 换成 `py -3`。每次只处理这个库。

```shell
python3 -X utf8 "<脚本>" pending --vault "<知识库>"
```

脚本每行输出一个文件的相对路径与 SHA-256 内容指纹。首次列出 `方法论/宏观与投资/` 的细笔记（含月度与观点记录）和 `raw/B站/` 的原始笔记。以后只列新增或修订的材料。缺少任一核心文件时，重新列出全部材料，清除本库旧进度，使分次补建时尚未处理的材料仍能被找到。

- 已有投资细笔记时，从这些笔记和引用开始；没有新视频也可以整理。若只缺核心文件，依据现有材料补建。库里只有模板或尚无可用的投资材料时，告诉用户可以发一条有字幕的投资视频，或补充带来源的投资笔记，再运行更新。此时不建空核心文件，不记录完成。
- 对待处理的原始视频，按 BV 号和分 P 辨认同一来源。看笔记头的 `bvid`、`part` 和来源链接，也兼容早期文件名和 URL 的 `p=`。未标分集时按第一 P 核对。查细笔记是否实际引用该分集，以及已覆盖哪些要点。仅在主题难辨或提炼不足时读全文字幕。纯非投资材料可以标为已筛过。
- 投资视频只有字幕或只提炼了一部分时，复用 `bilibili-to-obsidian` 的提取与合并规则，每期从本地字幕选 1～3 个点，先补齐细笔记，再融合到核心文件。分集不明、缺字幕或配套技能不可用时，把未处理完的原始笔记留到下次，继续处理其他材料。

## 合并两份核心文件

目标目录是 `方法论/宏观与投资/`。先读已有文件，再判断新材料是否改变要问的问题、应看的证据、适用条件或改判理由。

- **投资推演核心框架.md** 收录可复用的判断方法。围绕决策问题写清证据、成立条件和改判信号，来源缺少的条件留作缺口。反例可用于缩小旧规则的适用范围；不同意见保留各自的时间、前提和依据。重复案例留在细笔记。
- **决策问题与证据导航.md** 以实际问题为入口。每项说明该看什么，链接到实际存在的 `[[方法论/宏观与投资/细笔记#小节|显示名]]`。互补和意见相反的小节都可列入。细笔记调整小节名时，更新受影响的导航。
- 框架中的实质判断就近附原始来源。视频使用 `[[raw/B站/原始文件|来源]]` 和对应分集的时间戳。其他已有投资笔记按库规引用能核实的原始出处，缺出处的论断先留待补证。导航只做指路时可只链细笔记。首次出现的术语用一句话说明。合并产生的新解释用实际助手名标记，如“（Codex 推断）”或“（WorkBuddy 推断）”。当期预测、仓位和交易保留在带日期的细笔记。

## 保存进度

写前重读目标，写后确认改动。保留用户手写段落，标明 `reviewed: true` 的文件只追加；修正旧结论时指明对应条目。按库规用实际助手名称更新当日工作日记。首次有可用投资材料时创建缺失的核心文件。两份均已存在且无待处理材料时，直接给出现有文件链接。

只选择已经完成的 JSON 行，包括已筛过的非投资材料和重复案例。若补写了细笔记，再运行一次 `pending`，选择实际读过并合并的最终版本。在两份核心文件、细笔记和必要的日记均已保存后，把选中的原样行写入库外临时 UTF-8 文件并执行：

```shell
python3 -X utf8 "<脚本>" done --vault "<知识库>" --rows "<已完成行.jsonl>"
```

也可通过标准输入传入相同行。指纹已经变化的文件不会被这批记录覆盖。中断后对照已写内容继续，避免重复追加。进度库在本机按库的绝对路径区分；移动库或换设备会重新扫描。返回两份核心文件的链接、实际改变的判断及其出处，列出尚未处理的来源，并遵守库内的交付约定。
